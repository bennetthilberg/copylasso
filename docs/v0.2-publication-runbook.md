# CopyLasso v0.2 Publication Runbook

build, sign, notarize, staple, or package CopyLasso. The final release tag
continues to identify the exact source commit from which the approved candidate
was built.

## Phase 1 - Protected Preparation

Phase 1 begins only after the G43 publication-control pull request is merged to
protected `main`. Dispatch `.github/workflows/prepare-publication.yml` from that
exact protected-main commit and approve the existing `release` environment.

The workflow performs the complete canonical quality gate, then:

1. Downloads release `361203156` with authenticated GitHub access.
2. Verifies its draft/prerelease state, target, reviewed notes, four exact asset
   names, sizes, and GitHub SHA-256 records, and independently proves the
   lightweight RC tag still points directly to the frozen source commit.
3. Downloads and independently hashes all four restricted assets.
4. Reconstructs the G42 verification bundle and reruns Developer ID, package,
   notarization, Gatekeeper, version/build, architecture, entitlement, DMG,
   checksum, dSYM, and source-commit checks without rebuilding.
5. Resolves the pinned Sparkle 2.9.4 tools and exposes the production signing
   seed only to the final-appcast generation step.
6. Generates one signed `appcast.xml` whose enclosure is exactly:

   `https://github.com/bennetthilberg/copylasso/releases/download/v0.2.0/CopyLasso-0.2.0.dmg`

7. Confirms `v0.1.1` is still GitHub's latest public release, then creates one
   private, non-prerelease final draft targeting the frozen candidate commit.
   The draft contains only the approved DMG and checksum.
8. Uploads a private workflow handoff containing the feed-only bundle, candidate
   readback, final-draft readback, and content-free manifest.

The workflow accepts no dispatch input. It cannot create a tag, publish a
release, deploy a feed, replace an asset, or receive Developer ID or
notarization credentials.

Download the handoff with authenticated maintainer tooling and rerun
`scripts/audit-v02-publication.sh --handoff <directory>`. Stop if any readback,
digest, signature, or state differs.

## Phase 2 - Signed Tag And Publication

Phase 2 is the separately approved public transaction.

### Preflight

Before mutation, confirm:

- protected `main` contains the merged G43 control commit;
- the worktree is clean;
- `v0.2.0-rc.1` still points directly to the frozen candidate commit;
- candidate release `361203156` is still private, draft, prerelease, and has the
  same four restricted assets;
- no `v0.2.0` tag or release exists;
- the private final draft has exactly the two approved public assets and exact
  notes;
- the handoff appcast and enclosure signatures verify through Sparkle using the
  public key compiled into the candidate; and
- `v0.1.1` remains the latest public release.

### Feed Endpoint Preparation

Create a Direct Upload Cloudflare Pages project named `copylasso-updates`.
Associate `updates.copylasso.com` with the Pages project before changing DNS.
The authoritative DNS remains at Spaceship; add only a DNS CNAME for `updates`
pointing to the assigned `pages.dev` hostname. Do not move nameservers or
change the `copylasso.com` apex.

Wait for the custom hostname and TLS certificate to become active. Before the
release is public, `https://updates.copylasso.com/appcast.xml` must remain
absent rather than serving incomplete or unsigned metadata.

The production deployment directory contains exactly:

- `appcast.xml`
- `_headers`

There is no index page, general website, executable code, analytics, redirect,
or content endpoint. The headers require XML content, `nosniff`, and a
five-minute revalidation window with `no-transform`.

### Final Tag

Use the existing dedicated passphrase-protected release-tag SSH key. Create an
annotated signed `v0.2.0` tag with message `CopyLasso 0.2.0` on the frozen
candidate source commit. Verify it locally using a temporary allowed-signers
file, then push only `refs/tags/v0.2.0`.

GitHub readback must show an annotated tag object, a valid verified signature,
and an object that peels to the candidate source commit. The direct
`v0.2.0-rc.1` tag must remain unchanged.

Never move either tag.

### GitHub Release

Read the private final draft by numeric release ID. Publish that exact draft as
non-prerelease and latest. Resolve an ambiguous API result through exact
readback before retrying.

The final release has exactly two maintainer-uploaded assets:

- `CopyLasso-0.2.0.dmg`
- `CopyLasso-0.2.0.dmg.sha256`

Never replace a public asset. GitHub-generated source ZIP and tarball links are
expected and do not count as uploaded assets.

### Authenticated Feed

Only after the GitHub tag, release, and download URL pass readback, deploy the
exact handoff feed directory to the production Cloudflare Pages deployment.
Read `appcast.xml` through both the custom hostname and assigned Pages hostname
and compare the bytes with the private handoff before trusting the deployment.

The signed metadata must contain exactly one `0.2.0 (3)` item, the exact final
GitHub enclosure URL and byte length, the approved inline plain-text notes, and
no external release-notes URL.

## Public Verification

Perform all checks without authenticated download URLs:

1. Confirm the release is public, non-prerelease, latest, and still contains
   only the two approved assets with matching GitHub digests.
2. Confirm the signed annotated final tag and direct RC tag both identify the
   frozen source commit.
3. Download both generated source archives and compare their tracked content
   with the source tree at the final tag.
4. Fetch the updater feed and verify exact bytes, XML structure, feed
   signature, enclosure signature, version ordering, final URL, length, and
   inline notes.
5. In a fresh Safari private session, download the DMG and checksum so the DMG
   receives genuine quarantine metadata.
6. Verify checksum, Developer ID, notarization ticket, Gatekeeper, read-only
   two-item DMG layout, production bundle identifier, `0.2.0 (3)`, reviewed
   entitlements, and both architectures.
7. Reversibly stage the current installation, drag-install the public download,
   launch normally, and run a compact text, QR-precedence, success-sound,
   Settings, update-check, and quit/relaunch smoke.
8. Exercise the reviewed isolated older-updater fixture against the public
   feed. Confirm deferral, download, install/relaunch, exact candidate bytes,
   preserved preferences, and a subsequent up-to-date result.
9. Confirm the first-updater release notes explicitly tell `0.1.x` users to
   install `0.2.0` manually.

Retain content-free records outside the repository under a commit-addressed G43
directory. Do not retain credentials or updater content.

## Failure And Recovery

- Before a final tag exists, a helper may delete only the incomplete private
  final draft that it created in the same invocation.
- After the signed tag is pushed, do not delete or move it. Read back ambiguous
  GitHub state and resume only against the same tag, release ID, and bytes.
- After the release is public, do not delete it, replace assets, edit immutable
  evidence, or publish a corrected appcast automatically. Stop and obtain a
  separately reviewed remediation decision.
- If feed hosting fails after release publication, leave the immutable GitHub
  release intact and keep the feed absent until the exact signed metadata can be
  served.
- A source, application, package, note, entitlement, dependency, or artifact
  change invalidates the candidate and requires a new release candidate.

## G44 Handoff

G43 records live publication evidence only in ignored `roadmap.md` and external
content-free records. G44 separately dates the changelog from GitHub's actual
publication timestamp, updates released-state documentation, closes only
shipped and publicly verified issues, verifies the exact public local
installation, and reconciles protected `main`.
