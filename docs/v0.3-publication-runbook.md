# CopyLasso v0.3 Publication Runbook

## G56 v0.3.0 Publication

G56 publishes only the immutable candidate approved in G55. The candidate is
`v0.3.0-rc.1` at commit
`c99bec65be187c02b920b6519152ba935ec44253`, and its DMG SHA-256 is
`96f07eff7719f6c5b4b819af846d9ac825e13d4959d6f45d14d19fffa943bb96`.
The preparation and publication transaction must consume these bytes without rebuilding,
re-signing, re-notarizing, or changing the candidate.

### Phase 1: protected preparation control

Merge the reviewed G56 control pull request before dispatch. From the exact
protected `main` commit, dispatch `copylasso_prepare_v030_publication` with no
client payload. The workflow must finish canonical CI before entering the
protected `release` environment. It receives only the GitHub token needed to
read the private candidate and create a private draft, the expected Apple team
identifier needed for read-only package verification, and the Sparkle key in
the single metadata-generation step.

The workflow downloads the exact four candidate assets, verifies their pinned
sizes and digests, expands the restricted verification bundle, and repeats the
signature, notarization, Gatekeeper, version/build, architecture, entitlement,
nested-code, checksum, and package-layout checks. It then creates:

- one signed final-URL `appcast.xml` whose enclosure is the approved DMG at
  `https://github.com/bennetthilberg/copylasso/releases/download/v0.3.0/CopyLasso-0.3.0.dmg`;
- one feed-only deployment directory containing `appcast.xml` and `_headers`;
- one private, non-prerelease `v0.3.0` draft containing exactly the approved
  DMG and checksum; and
- one private handoff recording candidate, tag, draft, DMG, and appcast
  identities.

Preparation stops there. It cannot publish, create or move a tag, replace an
asset, deploy a feed, build an application, notarize, or accept an arbitrary
tag or candidate input. If a final tag or release already exists, or an API
mutation is ambiguous, exact readback must prove the intended private draft or
the workflow fails closed.

### Phase 2: immutable publication transaction

Download the private handoff from the successful preparation run and verify it
again locally before any mutation. Confirm that public `v0.2.2` is still the
latest release and that neither a `v0.3.0` release nor tag exists.

Create a signed annotated `v0.3.0` tag with message `CopyLasso 0.3.0` on the
candidate commit, verify it locally, push only that ref, and require GitHub's
annotated-tag object to report a valid verified signature and the exact
candidate commit. Publish the verified private draft by numeric release ID as
public, non-prerelease, and latest. Never move either tag or replace an
uploaded asset. After the public GitHub enclosure URL works, deploy only the
prepared feed bundle to the existing `updates.copylasso.com` Pages project.

For any timeout or ambiguous response, read back the exact tag, release ID,
asset set, and feed deployment before retrying. A mismatch is a stop condition,
not permission to delete or overwrite public state.

### Phase 3: public verification

From an unauthenticated browser, verify the release page, exact two assets, and
generated source archives. Download the public DMG and checksum with genuine
quarantine and repeat digest, Developer ID, notarization, Gatekeeper,
two-item-DMG, Universal 2, production-identifier, and `0.3.0 (6)` checks.

Exercise one clean installation and one public update from exact `0.2.2 (5)`
through Later, separate Download and Install and Relaunch consent, retained
preferences, successful post-update capture, and rollback rejection. Verify
the live appcast and enclosure signatures, final URL, length, build ordering,
and public cache/security headers. Publication does not relabel the accepted macOS 14 and direct high-water readback gaps
from G55 as passes.

Stop after recording immutable publication and public-verification evidence.
G57 separately dates the changelog, reconciles release-state documentation,
installs the final public build on the maintainer account, and closes only the
issues authorized by its scope.
