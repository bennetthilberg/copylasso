# CopyLasso v0.3 Private Candidate Qualification

G55 applies this procedure to one workflow-built `v0.3.0-rc.N` candidate from
the exact protected-main commit produced by the separately merged G54 pull
request. This record is completed with actual identifiers, digests, results,
and gaps after the protected run; it never treats the local G54 package as the
candidate.

## Protected Run Readback

1. Confirm the repository dispatch ran from `refs/heads/main` at the exact
   protected-main commit and accepted one positive canonical candidate number.
2. Require every ordinary arm64, x86_64, and maintained macOS runtime check to
   pass before the protected release job begins.
3. Read back a direct `v0.3.0-rc.N` tag at that exact commit and one private,
   draft, prerelease GitHub release. The draft must contain exactly four assets:
   the versioned DMG, checksum, dSYM, and restricted verification bundle.
4. Record GitHub's filename, byte length, and `sha256:` digest for each asset.
   Refuse an existing tag or release, a replacement upload, a moved tag, an
   unexpected asset, or an ambiguous mutation response.

## Candidate Byte Verification

Download all four assets from the private draft into a fresh external,
commit-addressed directory. Do not rebuild, re-sign, staple, repackage, rename,
or upload them.

- Match every downloaded length and SHA-256 digest to GitHub readback and match
  the checksum file to the exact DMG.
- Expand the restricted verification bundle and bind its payload and packaging
  commits to the protected-main commit and candidate tag.
- Rerun the current release-package verifier against the bundled app and exact
  DMG. Require production identity `io.github.bennetthilberg.copylasso`,
  `0.3.0 (6)`, both architectures, Developer ID secure timestamps, Hardened
  Runtime, reviewed entitlements, nested signatures, accepted notarization,
  stapled tickets, Gatekeeper, the read-only two-item DMG layout, matching dSYM
  UUIDs, checksum, manifest, and provenance.
- Validate the candidate's authenticated update metadata against the public key
  compiled into that exact app. Require one enclosure at the candidate URL,
  correct version/build/length, valid feed and enclosure signatures, and
  rejection of mutated metadata, mutated DMG bytes, and an unrelated key.

## Candidate Smoke Matrix

### Disposable-account clean-state preflight

Use a disposable local macOS account. Before entering it, quit every CopyLasso
process and reversibly stage any `/Applications/CopyLasso.app` outside
Applications; do not delete or inspect the maintainer's production data.
Within the disposable account, require all of the following before installation:

- `/Applications/CopyLasso.app` is absent;
- `defaults read io.github.bennetthilberg.copylasso` reports no domain;
- `~/Library/Containers/io.github.bennetthilberg.copylasso` and its encrypted
  history archive are absent;
- `security find-generic-password -s
  io.github.bennetthilberg.copylasso.capture-history -a archive-key-v1` reports
  no item, without requesting or printing secret data;
- CopyLasso is absent from Login Items & Extensions; and
- CopyLasso is absent from Screen & System Audio Recording.

Do not inspect raw TCC or login-item databases and do not use broad reset
commands. Any surviving app, preference, container, history key/archive, login
item, or Screen Recording row invalidates the clean-install run.

Use a fresh Safari download of the private DMG so macOS records genuine
quarantine metadata. Perform a clean install on a supported host and verify
Gatekeeper, drag install,
launch, onboarding, Screen Recording denial and recovery, Settings, About,
ordinary OCR, representative configured OCR languages, QR-over-text precedence,
all supported code formats, no-result, Escape, optional sound, rapid reuse,
focus preservation, Launch at Login reconciliation, and quit/relaunch.

Exercise capture history from its default-off state: opt in, capture text and a
code, relaunch, copy/delete/clear, confirm disable, and verify no screenshot or
plaintext archive. Recheck keyboard traversal, VoiceOver labels, light/dark and
accessibility appearances, single-display clamping, idle, and bounded repeated
use.

The private draft is not directly accessible to the disposable browser. First
download and verify the DMG and checksum with authenticated maintainer tooling
in the maintainer account. Place only those two verified files in a temporary
external directory and serve it on `127.0.0.1` at an unused high port. Download
both through Safari in the disposable account, require a nonempty
`com.apple.quarantine` attribute and matching checksum, then stop the server.
Never sign the disposable account in to GitHub, bind the server to every
interface, copy the app itself between accounts, or synthesize quarantine.

Test the authenticated update transition from the exact public 0.2.2 build to
the byte-identical private candidate through this isolated nonshipping staging
procedure; the historical G36 fixture is not evidence for G55:

1. With authenticated maintainer tooling, download the exact public 0.2.2 DMG
   and the four private candidate assets. Verify both packages independently and
   extract the public and candidate apps without modifying either source copy.
2. Make a disposable working copy of the public 0.2.2 app. Change only that old
   copy's `SUFeedURL` to `http://127.0.0.1:<high-port>/appcast.xml`, add only the
   local-network ATS allowance needed for the fixture, and re-sign that old copy
   with the maintainer's matching-team Developer ID identity and its original
   reviewed entitlements. Verify the re-signed fixture and record that it is no
   longer release-identical; it exists solely to redirect update discovery.
3. From the untouched candidate DMG and reviewed 0.3.0 notes, use the protected
   Sparkle Keychain identity to generate a one-item loopback appcast. Require
   the derived public key to match `SUPublicEDKey` in both apps, require the
   enclosure to be the exact candidate DMG bytes, verify the feed and enclosure
   signatures, and prove mutated metadata, mutated DMG bytes, and an unrelated
   key are rejected.
4. Serve only that appcast and exact candidate DMG from `127.0.0.1`. In the
   disposable account, install the redirected old-app copy and create deliberate
   shortcut, updater, sound, Launch at Login, and permission-history state that
   public 0.2.2 actually supports. Then exercise Later, Download, and Install
   and Relaunch.
5. Stop the loopback server immediately after the transaction. Verify the
   installed application against the untouched candidate payload manifest,
   signature, notarization, version/build, and architectures. Confirm preference
   retention, build-high-water advancement to `6`, U.S. English as the new
   language default, capture history off with no key or archive, normal capture
   after relaunch, offline failure isolation, tamper rejection, and rollback
   rejection. Exercise history only after explicitly opting in on 0.3.0.

Only the old discovery fixture is modified. If the installed post-update app
does not byte-match the candidate manifest, the candidate fails; never re-sign,
patch, or substitute the v0.3 candidate to make this smoke pass.

## Retained Gaps And Disposition

Record every unavailable physical, accessibility, display, OS-version, update,
or lifecycle row as passed, failed, blocked, or explicitly accepted. Never infer
a pass from G54 automation or historical G24/G41 evidence. A product, signing,
packaging, or configuration correction creates a new candidate number and
repeats every affected gate; candidate assets and tags are never replaced or
moved.

Real clean-host qualification on the minimum supported macOS 14 must pass. It
is a release-blocking G55 gate and cannot be accepted, waived, or inferred from
the hosted macOS 15 lane. Other unavailable non-gating rows may receive an
explicitly documented accepted-gap disposition.

## Approval Gate

Read back the final private release, tag, four assets, checks, review state, and
completed evidence at the exact candidate commit. Obtain explicit maintainer approval
of that immutable candidate before G56. Do not publish, create the
final tag, prepare a public release, or deploy authenticated update metadata in
G55.
